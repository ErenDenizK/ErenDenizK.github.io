# Research: tools and skills for motion and drawing (2026-10-09)

**Status:** history. Tools survey for the craft round.

Track 4 of `docs/history/plan-2026-10-craft-round.md`. Question: which separate tools, libraries or agent skills would
materially raise the quality of animation and drawing on this site (dark ground, quiet type,
one morphing 3D object per tab, a log with code-drawn illustrations, project focus views),
given that the lead works headless and the owner can run GUI apps on a Mac.

**Evidence grades.** **E** verified here: run, measured or read at source in this container
on 2026-10-09 (npm registry, bundles built with esbuild, repos cloned). **P** primary source
(vendor docs, release notes) seen through search, not run. **F** secondary sources (reviews,
forums, catalogues). **M** recollection, unconfirmed.

**Sizes** are minified + gzip -9 of an esbuild bundle importing only what is named, `three`
external (E). WASM files measured the same way. Budgets from `2026-10-stack.md` §6: content
JS ≤ 15 KB gz, desktop 3D ≤ 250 KB, mobile ≤ 150 KB.

## Summary

1. **The quality gap is craft, not missing libraries.** three r186 already ships TSL post
   nodes (bloom, DOF, TRAA, GTAO, SSR, LUT, *TransitionNode*), MaterialX noise and a
   ShaderToy→TSL transpiler (E). Most add-ons would duplicate that.
2. **GSAP is the one motion library worth adding**, but it does not fit the 15 KB content
   budget (core alone 27.5 KB, E). It belongs in a lazily loaded enhancement chunk; the content
   path stays on CSS, `linear()` springs and native View Transitions.
3. **Drawing is build-time.** d3-shape, perfect-freehand, rough.js and svgo produce static,
   seeded, optimised SVG in Node (E): zero runtime bytes, still twins for free.
4. **GUI-authored formats (Rive, Lottie, Spline, Unicorn Studio) cost the most and fit
   worst**: heavy WASM runtimes, paid export, and output the agent cannot diff or regenerate.
5. **Skills:** the official `gsap-skills`, `frontend-design` and `playground` are worth
   having; most community three.js skills are stale (r160) or generic.

## 6. Risks across the toolkit

- **Weight creep:** every runtime library must name its chunk and pass `size-limit`; GSAP never
  enters the content path.
- **Licence drift:** GSAP's licence is vendor-controlled; pin the version and keep the
  native path (View Transitions, CSS) complete, so removing GSAP degrades polish, not content.
- **Opaque assets:** reject formats the agent cannot regenerate from source (`.riv`, Spline
  scenes, `.blend` without a script). Matches ADR-0005's "scripts committed, never `.blend`".
- **Skills steer:** vendor skills recommend their own library; ADRs decide, skills inform.

### Install plan

1. **Now (agent session, nothing in the repo):** enable the `frontend-design` and `playground`
   plugins and add `greensock/gsap-skills` via the plugin marketplace; configure Playwright MCP
   (pinned `@playwright/mcp@0.0.83`) and `chrome-devtools-mcp@1.10.1` in the session config.
2. **Prototype F (`prototypes/f-*`, own `package.json`):** `gsap@3.15.0`, `three@0.186.1`,
   `lil-gui`, `stats-gl`; build-time `svgo`, `d3-shape`, `perfect-freehand`, `sharp`. Try
   TransitionNode for the tab morph and Flip vs View Transitions for the focus view, measure
   both against the budgets, then write the motion ADR (ADR-0007 in `docs/history/plan-2026-10-craft-round.md`).
3. **Level 2 scaffold:** the same pins move into the Astro app; `size-limit` entries per chunk
   (content, focus-view enhancement, desktop 3D, mobile 3D); Renovate groups for three and gsap.
4. **Owner, when convenient:** install Blender 5.2 (free) to review object lighting; enable
   Safari's Develop menu for iPhone inspection; record an Eat Map Simulator clip.
