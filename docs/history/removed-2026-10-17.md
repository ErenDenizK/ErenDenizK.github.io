# Code removed on 2026-10-17

The new Home became the site root and the Record moved onto the two-page token set (review row S38;
ADR-0019). The four-page site's pages went, and with them every component, script and stylesheet that
nothing imports any more. This file is the record: what each piece was, why it went, and how to get it
back. Every file is still in git. The last commit that holds all of them is `8051e31` (on
`wip/r6-work`, before the promotion). To restore one file:

```sh
git show 8051e31:<path> > <path>
```

Why delete and not move: the same reason as on 2026-10-15 (`removed-2026-10-15.md`). `tsconfig.json`
type-checks every file in the repo, and dead code in the tree steers new work back to the old design.

How "nothing imports it" was decided: a reachability pass from every page, `content.config.ts`,
`astro.config.mjs` and the integrations, following `import`, `import()`, `import.meta.glob`, CSS `url()`
and worker URLs. Files it could not reach and that belong to the four-page site are listed below. Four
unreached files of the new Home stay, because they are not four-page code: `src/one/Bostanci.astro` and
`src/one/Plate.astro` (the first screen's earlier forms, waiting for the owner's A/B/C answer),
`src/one/work/scripts/ease.ts` and `src/one/work/tools/props.mjs` (the Work lane's helpers).

## Tools

`tools/palette/check.mjs` measured the four-page house theme from `global.css` and the other four-page
stylesheets. Its base is now `src/one/tokens.css`; the house theme `dark` is gone with its files, and the
Record's pairings on the new set are rows in `tools/palette/one.mjs`. The `site` and `embassy` rows stay
in the file as the record of what the old theme measured; the product worlds still run, advisory.
`npm run palette:lab` read the theme candidates from `lab-themes.css`; with the file gone it finds none.
